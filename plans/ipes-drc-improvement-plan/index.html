    Comprehensive Architectural Plan: .ipes Standardization, Wire-Based DRC & Platform Improvements¶

    Executive Summary¶

    Based on the completion and validation of all 21 converter and multi-domain tutorials, this plan addresses the core technical bottlenecks identified during testing: 1. The .ipes Topic (Highest Priority - COMPLETED in Phase 1): Standardized all project files to plain UTF-8 text (eliminating binary GZIP confusion in git and Python tools), with zero backward compatibility baggage while guaranteeing 100% of repository project files continue to validate and simulate. 2. Wire-Based Ground & Net Mapping in DRC (Phase 2 - COMPLETED): Reworked CircuitValidator to geometric coordinate netlist resolution aligned with simulation engine semantics (NetlistBuilder), eliminating false short-circuits from wire crossings, handling wire-labeled grounds, and supporting name-based gate coupling and probe measurement node resolution. 3. Sequential Platform Improvements (Phases 3–7): Multi-domain synthesis schema, specialized thermal/magnetic metrics, pre-flight topological validation, parameterized control libraries, and developer ergonomics (Python SDK, SVG exporter).

    Objective¶

    Allow declarative generation of multi-domain circuits (thermal networks, coupled magnetics, non-linear inductors) through the JSON MCP interface with full DRC validation, MNA matrix fidelity, and simulation execution.

        Def --> Control[Control Probes & Scripts]
    end
    subgraph CircuitBuilder Synthesis Engine
        Coupled -->|Auto-Upgrade typ 2 to typ 12 LK_LKOP2| Sync[Synchronize Slot 10 Matrix A Companion]
        Sync --> LKM[Generate typ 9 LK_M Coupler]
        NonLin --> Extra[Generate nonlinX/nonlinY Curves & Flags]
        ThermNet --> Ladder[Generate 4-Pitch RC Ladder]
        Ladder --> Loss[Inject TH_PvCHIP & TH_FLOW]
        Ladder --> Tamb[Generate TH_TEMP & TH_GLOBAL_TERMINAL]
        LK & ThermComp & Ladder --> Wires[Explicit connectorType LK=0 / CTRL=1 / THERM=2 & Labels]
    end
    subgraph Simulation & DRC Engine
        Wires --> DRC[CircuitValidator: Multi-Domain Checks]

    end

    Key Technical Deliverables¶

    1. Component Registration in ComponentCatalog:
    2. COUPLED_INDUCTOR (LK_LKOP2, typ 12) with nominal inductance and companion slot 10 mapping.
    3. MUTUAL_INDUCTANCE (LK_M, typ 9) with coupling coefficient \(k \in (0, 1]\).
    4. NONLINEAR_INDUCTOR (typ 2) with current/inductance characteristic curves.
    5. Thermal domain catalog: TH_RTH (46), TH_CTH (47), TH_FLOW (44), TH_TEMP (45), TH_AMBIENT (48), TH_PvCHIP (41), TH_GLOBAL_TERMINAL (50), and human-friendly aliases (THERMAL_RESISTOR, THERMAL_CAPACITOR, HEAT_FLOW_SOURCE, AMBIENT_TEMPERATURE, THERMAL_POWER_LOSS, PV_CHIP, THERMAL_GROUND).
    6. Coupled Inductor Synthesis (CircuitBuilder):
    7. Accepts declarative coupled_inductors: [ { name, inductor1, inductor2, k } ] or MUTUAL_INDUCTANCE components.
    8. Automatically upgrades referenced inductors from generic INDUCTOR (typ 2) to COUPLED_INDUCTOR (typ 12), initializing slot 10 (INDEX_EFFECTIVE_L = slot[0]) to satisfy MNA matrix requirements.
    9. Generates LK_M (typ 9) coupler linking the pair by both UIDs in rawParameters[1..2] and names in parameterStrings[0..1].
    10. Electro-Thermal Network Synthesis (CircuitBuilder):
    11. thermal_networks declarative synthesis:
      • Supports model_type: "foster" (parallel \(R_{th} \parallel C_{th}\) ladder stages) and "cauer" (series \(R_{th}\) with shunt \(C_{th}\) to ambient).
      • Standardized 4-grid-unit vertical pitch geometry ensuring exact pin coincident alignment across stages.
      • Couples semiconductor loss via TH_PvCHIP (typ 41) referencing target_switch by name and UID, and/or injects heat flow via TH_FLOW (typ 44).
      • Binds ambient boundary temperature via TH_TEMP (typ 45) referenced to thermal ground TH_GLOBAL_TERMINAL (typ 50).
    12. Non-Linear Saturating Inductor Modeling:
    13. Discretizes \(i(L)\) curves from saturation_table or saturation_currents/saturation_inductances vectors into nonlinX[] and nonlinY[] extra lines with isNonLinear true.
    14. DRC & Wire Connector Integration (CircuitValidator):
    15. Explicit connectorType stamped on all connections (0 = LK, 1 = CONTROL, 2 = THERMAL).
    16. Handled single-pin geometry for TH_GLOBAL_TERMINAL (typ 50) and TH_PvCHIP (typ 41), binding thermal ground 0 without false dangling pin diagnostics.
    17. Correctly handles zero-terminal couplers (LK_M, typ 9) without false short-circuit or floating-terminal warnings.
    18. Voltmeter probes support node-pair measurements (nodeA, nodeB) as well as component branch voltage coupling.

    Phase 4: Domain-Specific Metrics in gecko_measure_metrics (COMPLETED)¶

    Objective¶

    Extend automated post-simulation waveform metrics to cover thermal, magnetic, and mechanical variables without streaming raw time-series over stdio.

    Implementation Summary¶

    1. Multi-Domain Analytics Engine (PowerMetricsCalculator):
    2. Thermal Metrics:
      • Steady-state junction temperature: \(T_{j,ss} = \overline{T_j(t)}\)
      • Peak thermal ripple: \(\Delta T_j = T_{j,max} - T_{j,min}\)
      • Temperature rise above ambient: \(\Delta T = T_{j,ss} - T_{ambient}\)
      • 2% tolerance band settling time (\(t_{settle}\)) computed across the full transient profile.
      • Equivalent 1st-order thermal time constant \(\tau_{th}\) computed from \(63.2\%\) rise time.
    3. Magnetic Metrics:
      • Peak flux \(\hat{\Phi}\) and core flux excursion \(\Delta \Phi = \Phi_{max} - \Phi_{min}\).
      • Peak flux density \(\hat{B} = \hat{\Phi} / A_e\) and flux density excursion \(\Delta B = \Delta \Phi / A_e\).
      • Steinmetz core loss density: \(P_{vol} = k \cdot f^\alpha \cdot \hat{B}^\beta\) (\(\text{W/m}^3\)).
      • Total core loss: \(P_{total} = P_{vol} \cdot V_e\) (\(\text{W}\)).
      • Peak inductor current \(\hat{I}\), RMS current, peak-to-peak ripple \(\Delta I\), ripple percentage \(\%\).
      • Core saturation safety margin: \(\text{Margin}_{sat} = 1 - \hat{I} / I_{sat}\).
      • Peak stored inductive energy: \(E_{mag} = \frac{1}{2} L \hat{I}^2\).
    4. Mechanical Metrics:
      • Rotor angular velocity mean speed \(\bar{\omega}\) (rad/s) and conversion to RPM.
      • Speed ripple (pk-pk and percentage).
      • Reference speed tracking error percentage against target_speed.
      • Settling time to within 2% band of target_speed.
      • Mechanical torque mean \(\bar{T}\), peak torque, torque ripple (pk-pk and percentage).
      • Average shaft mechanical power: \(P_{mech} = \overline{\omega(t) \cdot T(t)}\).
    5. Electrical Power Metrics: 100% backward compatibility preserved for \(P_{in}\), \(P_{out}\), \(S_{in}\), power factor, and conversion efficiency.
    6. Auto-Detection: Automatic heuristic detection of thermal (tj, temp, junction), magnetic (phi, flux, i_l), and mechanical (omega, speed, rpm, torque) probes if explicit signal lists are omitted.
    7. Schema & Tool Registration (GeckoTools):
    8. Exposed all multi-domain parameters (thermal_signals, ambient_temperature, flux_signals, i_inductor_signals, core_area_m2, core_volume_m3, i_sat, inductance, steinmetz_k, steinmetz_alpha, steinmetz_beta, frequency, speed_signals, torque_signals, target_speed).
    9. Wired measureMetrics() directly to PowerMetricsCalculator.calculate(csv, args).

    • PowerMetricsCalculatorTest.calculatesMagneticMetricsWithSteinmetzAndSaturation: validates peak flux, excursion, flux density, Steinmetz loss density & total loss, current peak/RMS, saturation margin, and stored energy.
    • PowerMetricsCalculatorTest.calculatesMechanicalMetricsWithSpeedSettlingAndTorque: validates rotor speed, RPM, speed ripple, target settling, tracking error, torque mean/ripple, and shaft mechanical power.

    Phase 5: Pre-Flight Topology Checks (Singular Matrix Prevention) (COMPLETED)¶

    Objective¶

    Catch topological degeneracies in CircuitValidator before the MNA solver executes, preventing numerical singularity crashes (SingularMatrixException) and providing structured, actionable diagnostics with suggested_fix guidance.

    Architecture & Rules Implemented¶

    flowchart TD
    subgraph PreFlight Topology Verification
        A[Canonical Nets & Component Map] --> B{Rule 6: Ideal Voltage Source Loop?}
        B -->|Cycle in Voltage Branch Subgraph| B1[ERROR: VOLTAGE_SOURCE_LOOP<br/>Suggest series damping resistor]
        B -->|Acyclic Subgraph| C{Rule 7: Inductive Cutset?}
        C -->|Inductor in series with Current Source| C1[ERROR: INDUCTIVE_CUTSET<br/>Suggest parallel snubber/resistor]
        C -->|Series Inductors without Impedance| C2[WARNING: INDUCTIVE_CUTSET<br/>Suggest combining equivalent L]
        C -->|Valid Impedance Paths| D{Rule 8: Active Switches Gated?}
        D -->|Switch missing GATE block or control driver| D1[WARNING: UNCONNECTED_GATE<br/>Suggest coupling GATE block]
        D -->|Gating Confirmed| E[Clean Pre-Flight Gate]
    end

    Key Technical Deliverables¶

    1. Rule 6: Voltage Source Loop Check (VOLTAGE_SOURCE_LOOP):
    2. Ideal voltage sources (typ 4) introduce auxiliary current variables in Modified Nodal Analysis (MNA). A closed loop of ideal voltage sources creates linearly dependent auxiliary equation rows/columns, causing solver singularity.
    3. Implemented disjoint-set cycle detection DisjointSet<String> vsUf on voltage source branch endpoints (net0, net1).
    4. Successfully catches parallel pairs (\(V_1 \parallel V_2\)) and closed polygonal loops (\(V_1 \to V_2 \to \dots \to V_k \to V_1\)) in \(O(E \alpha(V))\) time without false positives on 3-phase star sources.

    5. Diagnostic: ERROR: VOLTAGE_SOURCE_LOOP with concrete suggested_fix ("Insert an internal series damping resistor (e.g. 10 mOhm) or remove redundant parallel voltage source branches to break the ideal voltage source loop.").

    6. Rule 7: Inductive Cutset Check (INDUCTIVE_CUTSET):

    7. Inductors enforce current continuity. Connecting an inductor in series with an ideal current source (typ 5) forces conflicting current derivatives (\(L \frac{di}{dt}\) singularity).

    8. Evaluates node-degree and component sets on non-ground circuit nets:

      • Error: Net connecting inductor (typ 2, 12) directly in series with ideal current source (typ 5) without damping path.
      • Suggested Fix: "Add a parallel damping resistor (e.g. 1 MOhm) or snubber across the inductor branch to avoid an ideal inductive current cutset."
      • Warning: Net connecting two inductors in series with no intermediate branch or load impedance.
      • Suggested Fix: "Combine the two series inductors into a single equivalent inductor (L_total = L1 + L2) or add a parallel damping resistance."

    9. Rule 8: Unconnected Gate Check (UNCONNECTED_GATE):

    10. Active semiconductor power switches (typ 7 Thyristor, typ 8 Triac, typ 10 GTO, typ 11 IGBT, typ 28 MOSFET, typ 33 BJT) require gating control. An uncoupled switch remains statically open or in its initial condition, often indicating a schematic oversight.
    11. Checks:
      • coupledReferenceID pointing to switch UID.
      • parameterString / target name matching switch name.
      • Script block references in sourceCode, staticCode, and staticVars.
      • Physical terminal connectivity (for BJT base terminal).

    12. Diagnostic: WARNING: UNCONNECTED_GATE with concrete suggested_fix ("Add a GATE block (typ 6 / 1000) coupled to switch '' or provide a gating control signal.").

    13. Repository-Wide Structured suggested_fix Coverage:

    14. Extended CircuitValidator.Diagnostic record to optionally carry suggestedFix.
    15. Preserved full 4-argument constructor backward compatibility (Diagnostic(level, rule, comp, msg)).
    16. Serialized suggested_fix into JSON diagnostic payload across all 11 existing and new DRC rules:
      • SHORT_CIRCUIT: Disconnect shorted terminal or reroute branch.
      • MISSING_GROUND: Connect node '0' or place LK_GLOBAL_TERMINAL (typ 31).
      • FLOATING_NET: Connect open terminal or tie to ground/bus.
      • DANGLING_PROBE: Wire probe terminals or point to valid measurement node vector.
      • DANGLING_GATE: Target valid semiconductor switch UID or name.
      • INVALID_GATE_TARGET: Retarget to active switch.
      • NATIVEC_NO_LIBRARY: Build or configure C shared library path.
      • SCRIPT_COMPILE_ERROR: Statement-level syntax fix.
      • EMPTY_SCRIPT: Supply script logic or remove empty block.
      • UNBALANCED_BRACES: Match open/closing brace count.
      • DIVIDE_BY_ZERO_RISK: Insert zero-guard before division.

    Phase 6: Parameterized Control Block Library (COMPLETED)¶

    Objective¶

    Provide built-in, pre-verified control blocks in gecko_create_circuit to avoid repetitive manual scripting and boilerplate MNA control wiring.

    Architecture & Synthesis Engine¶

    flowchart TD
    subgraph Parameterized Control Block Synthesis
        A[JSON Circuit Request] --> B{Parameterized Block Detection}
        B -->|SPWM_GENERATOR| C[Carrier / Reference Comparator Engine]
        B -->|PI_CONTROLLER| D[Discrete Anti-Windup PI Engine]
        B -->|DEADTIME_GENERATOR| E[Turn-on Blanking Delay Engine]

        C --> F[Auto-Wire Signals to ctrlNetToPoints]
        D --> F
        E --> F

        C -.->|Declared switches| G[Auto-Generate GATE Blocks]
        E -.->|Declared switches| G

        F --> H[High-Precision MNA Simulation Engine]
        G --> H
    end

    Components Implemented¶

    1. SPWM_GENERATOR (Aliases: SPWM, PWM_SPWM):
    2. Carrier Generation: Symmetrical triangular carrier at configurable switching frequency (\(f_{carrier}\), default 10 kHz).
    3. Modulation Reference: Internal sinusoidal reference with modulation index \(m_a\) and grid frequency \(f_{grid}\) (default 50 Hz), or external modulation signals (in_signals: ["v_mod"]).
    4. Topological Outputs:
      • Single PWM output (out_signals: ["pwm"]).
      • Half-bridge complementary pair (out_signals: ["g_hi", "g_lo"]).
      • Full-bridge 4-switch inverter (out_signals: ["g1", "g2", "g3", "g4"]).
      • Three-phase 6-switch bridge (out_signals: ["g1", "g4", "g3", "g6", "g5", "g2"]) with \(120^\circ\) symmetric phase separation.
    5. Integrated Dead-Time: Configurable interlock blanking delay \(t_d\) preventing cross-conduction shoot-through.

    6. Auto-Gate Coupling: Declaring switches: ["S1", "S2", ...] automatically instantiates coupled GATE blocks without manual wiring.

    7. PI_CONTROLLER (Aliases: PI_REGULATOR, PI_ANTI_WINDUP):

    8. Discrete PI Architecture: Proportional gain \(K_p\) and integral gain \(K_i\) (or integration time \(T_n = K_p / K_i\)).
    9. Automatic Error Subtraction: When 2 inputs are supplied ([reference, feedback]), the block automatically calculates \(e(t) = v_{ref} - v_{meas}\).
    10. Dynamic Anti-Windup Clamping: Clamps output within \([y_{min}, y_{max}]\) and halts integration whenever actuator saturation occurs in the direction of error, eliminating integrator windup overshoot.
    11. Optional Reset Input: Third input channel (\(xIN[2] > 0.5\)) forces instantaneous integrator reset to zero.

    12. State Persistence: Supports non-zero initial integrator condition \(y_0\).

    13. DEADTIME_GENERATOR (Aliases: DEADTIME, DEAD_TIME):

    14. Shoot-Through Protection: Converts single PWM input into complementary high-side and low-side switching signals with precise turn-on blanking delay \(t_d\) (default \(1.0\ \mu\text{s}\)).
    15. Robust State Tracking: Dynamic rising/falling edge timer tracking operating at exact simulation timestep precision.

    16. Auto-Gate Coupling: Directly drives high-side and low-side switches declared via switches or switch_hi / switch_lo.
